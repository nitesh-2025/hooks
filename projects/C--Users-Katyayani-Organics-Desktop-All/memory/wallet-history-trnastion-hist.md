Facts found by reading the real backends:
- Roster `/kyc/agent_v2` (legacy utilities service) returns **active agents only** (`is_active: true`), so deactivated owners / TLs are missing → `resolveOwner` asks nest `GET /agents/:agent_id` (no active filter, any role, returns `agent_manager`) for each agent the roster lacks. Nest also has `GET /agents/all` (everyone, heavy) and `/agents/directory`.
- Nest list rows have **no phone field**; PII search is an exact match; `myteam` accepts boolean/"true".

- CN/UTR → customer mapping exists only in Stockship, so that lookup necessarily precedes nest. Non-admins use the exact `GET /utr/:number` only (the partial `GET /utr?search=` returns up to 10 other customers' UTR docs to the browser); admins keep partial search.
- It is a UI rule only: the Stockship wallet API and nest `GET /retailers/:id` are unscoped server-side.
